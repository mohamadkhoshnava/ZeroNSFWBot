# Test images

Two folders, scored by `scripts/eval_images.sh` against a running detector.

```
assets/test_images/
├── sfw/    committed — synthetic, obviously safe
└── nsfw/   empty and gitignored — you supply this
```

## `sfw/` — committed

Generated by `assets/generate_sfw_samples.py` (`make gen-images`): gradients,
shapes, a checkerboard, and `ocr_probe.png`, which has `join t.me/example`
rendered into it so the `/ocr` endpoint and the `profile_ocr` filter can be
exercised without any adult material.

They verify that the model is loaded and wired up correctly, and that it does
not flag ordinary images. They cannot tell you whether the model *catches*
anything — for that you need the other folder.

## `nsfw/` — you provide it

Deliberately empty and gitignored. This repository does not ship, generate, or
link to adult material.

To measure real recall, drop your own labelled positives here. In practice the
most useful set is the one from your own moderation history: profile pictures of
accounts your admins have already banned, exported before you delete them.
Nothing leaves your machine — the evaluation runs against your local detector
container.

`scripts/eval_images.sh` skips this folder cleanly when it is empty, and the
test suites treat both folders as optional rather than failing.

## Running an evaluation

```bash
docker compose up -d detector
make gen-images
./scripts/eval_images.sh
```

The script prints a per-image NSFW score plus, when both folders are populated,
accuracy and the false-positive/false-negative counts at each candidate
threshold — which is how you pick the number for `/nsfw → Threshold` rather
than guessing.
